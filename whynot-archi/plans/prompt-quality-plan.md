# 와이낫 영상 품질 개선 계획 — 프롬프트 연출 단계 추가 (초안 v1)

작성 2026-09-30 · 근거: `whynot-archi/AI-POC-whynot/docs/vpoc1/PRD.md`(6.5 조립 · 부록 D) · `regen-plan.md` · `phase2-handoff.md`
**주의: 실제 코드(`app/src/vpoc/`)를 보지 않고 문서만으로 세운 계획이다.** 코드 확인 후 1단계에서 수정한다.

## 0. 문제 정의

사용자는 "두 남자는 F1 레이서이고 원수지간이다" 같은 짧은 문장을 넣는다. 지금 구조는 이것을 **짧은 틀에 끼워 넣은 프롬프트**로 Luma Ray2 에 보낸다.
Luma Ray2 자체는 좋은 모델인데 결과 품질이 낮은 것은, 모델보다 **입력(프롬프트 · 해상도 · 시작 프레임)** 쪽 원인이 크다고 본다.

## 1. 원인 분석 (문서 근거)

| # | 원인 | 근거 | 영향 |
|---|---|---|---|
| C1 | **프롬프트가 고정 틀 한 줄이다** — `{STYLE}. {LOCATION}. {인물 외형}. {ACTION}. {CAMERA}.` | PRD 6.5 | 조명 · 분위기 · 색감 · 렌즈 · 질감 · 시간에 따른 움직임이 샷마다 거의 없다. 모델이 나머지를 "평균값"으로 채운다 |
| C2 | **동작 묘사가 한 문장(260자)뿐이다** · "한 샷에 한 동작" | PRD 6.5 · 부록 D-2 · D-4 | 5초 동안 무엇이 어떻게 변하는지(시작 → 끝)가 없다. 움직임이 밋밋하거나 어색하다 |
| C3 | **인물 외형 문장이 예산을 가장 많이 쓴다** — 200자 × 최대 2명 = 400자 | PRD 6.5 | 2인 샷은 1,200자 중 3분의 1이 정지된 외형 설명이다. 장면 · 움직임 묘사가 밀려난다 |
| C4 | **화풍 문자열이 모든 작품에 똑같다** (`Cinematic live-action film footage, photorealistic, …`) | PRD 6.5 | 작품마다 색감 · 조명 톤이 없다. "F1 야간 피트레인" 과 "학교 교무실" 이 같은 룩이다 |
| C5 | **프롬프트를 쓰는 AI 가 "연출" 지시를 받지 않는다** — 분석 · 계획 도구는 짧은 필드를 채우고 예산 · 금지어 검사를 통과하는 데 맞춰져 있다 | 부록 D-1 · D-2 | 영상용으로 풍부하게 "다시 쓰는" 단계가 없다 |
| C6 | **540p** | D-L10 | 해상도 자체가 낮다. 720p 는 비용 2배라 1단계에서 뺐다 |
| C7 | **텍스트만으로 영상 생성** — 시작 프레임(frame0)은 1인 · AI 이미지일 때만(P1) | PRD 5.1 · 6.5 | 첫 장면의 구도 · 화질을 모델이 처음부터 만든다. 이미지로 시작하면 화질 · 구도가 안정되는 경우가 많다 |

> Luma Ray2 실효 입력은 모델 카드 기준 약 300토큰(PRD 5.1). **프롬프트를 무작정 길게 하면 뒤쪽이 무시될 수 있다.** 따라서 목표는 "길게" 가 아니라 **"같은 길이 안에 영상에 효과 있는 정보로 채우기"** 다. 길이 효과는 실험으로 확인한다(E-3).

## 2. 해결 방향 — "연출 단계(Director)" 추가

사용자 문장과 확정된 계획 사이에 **AI 연출가** 를 한 번 더 둔다. 사용자 입력 · 흐름 · 화면은 그대로이고, 서버에서 샷 프롬프트를 만드는 방식만 바뀐다.

```
지금:  사용자 문장 → Claude 분석(②) → Claude 샷 계획(③) → 고정 틀 조립 → Luma
개선:  사용자 문장 → Claude 분석(②) → Claude 샷 계획(③) → ★ 연출 단계 → 조립 · 검사 → Luma
                                                      ├ 작품 룩 1개 (모든 샷 공통)
                                                      └ 샷별 연출 (시간 흐름 · 조명 · 카메라)
```

### 2-1. 작품 룩 (계획당 1개, 모든 샷 공통 — 일관성 유지)

`story.lookEn` 을 새로 만든다. 고정 화풍 문자열(C4)을 대체하지 않고 **뒤에 덧붙인다**(화풍 접두어는 맨 앞 유지).

| 항목 | 예 (F1 야간 피트레인) |
|---|---|
| 색감 | teal-and-amber color grade, deep blacks |
| 조명 | hard sodium floodlights, wet reflections, rim light on faces |
| 질감 · 렌즈 | anamorphic 35mm, shallow depth of field, light film grain |
| 분위기 | tense, charged silence after the race |

### 2-2. 샷별 연출 필드 (계획 도구 `emit_shots` 확장 — 추가만)

| 새 필드 | 내용 | 예산(초안) |
|---|---|---|
| `beatsEn` | 5초 안의 변화 2단계 — "시작 상태 → 끝 상태" | 260자 (`actionEn` 대체) |
| `framingEn` | 구도 · 인물 배치 · 전경/배경 | 80자 |
| `cameraEn` | 카메라 움직임 + 속도 (기존) | 80자 |
| `lightEn` | 이 샷의 빛 (작품 룩 안에서) | 80자 |
| `detailEn` | 화면을 살리는 구체 디테일 1~2개 (물방울, 헬멧 반사, 흩날리는 종이 등) | 100자 |

### 2-3. 인물 외형 압축 (C3)

- `appearanceEn`(200자, 캐릭터 이미지 · 시트용)은 그대로 둔다.
- 영상 프롬프트용 **`appearanceShortEn`(약 100자)** 을 분석 단계에서 한 번 만들고, **모든 샷에서 글자 하나 다르지 않게** 쓴다 — 기존 일관성 장치(같은 문자열 반복)는 유지하면서 예산을 절반으로 줄인다.
- 효과는 실험 E-2 로 확인한다(외형이 짧아져 일관성이 떨어지면 되돌린다).

### 2-4. 새 조립 틀 (초안 — 순서는 실험 E-4 로 확정)

```
{STYLE}, {LOOK}. {FRAMING} in {LOCATION}. {C1_SHORT}[; {C2_SHORT}]. {BEATS}. {LIGHT}. {DETAIL}. {CAMERA}.
```

기존 규칙은 그대로 지킨다: 영어만 · 캐릭터 이름 금지(handle 로 지칭) · 부정어 금지 · 자동 절단 금지(넘으면 '검토 필요') · 1,200자 상한(실험 E-3 결과로만 조정).

### 2-5. 연출 AI 모델

- 기본: 지금과 같은 Claude Sonnet 4.5 (계획 호출의 프롬프트만 강화 — 추가 호출 없음, 비용 거의 동일)
- 대안: 연출만 더 강한 Claude 모델로 분리 호출. **이 계정 Bedrock 에서 쓸 수 있는 모델인지 확인 필요**(D-L05: 모델 고정, 조용한 대체 금지 — 바꾸면 설정 키로 명시)

## 3. 품질 레버 3개 — 연출과 따로 켜고 끈다

| 레버 | 내용 | 비용 변화 | 필요 결정 |
|---|---|---|---|
| L1 연출 단계 | 위 2장 | 샷당 +0.01 USD 미만(Claude) | 없음(추가 기능, 스위치로 끔) |
| L2 720p | `VPOC_RESOLUTION=720p` — `CAPS` 에 이미 있음 | 샷당 3.75 → **7.50 USD** | **D-L10 변경 승인** |
| L3 샷 시작 프레임 | 연출 프롬프트로 SD3.5 가 **샷 첫 장면 이미지**(인물 초상이 아니라 장면)를 그리고 frame0 으로 넣는다. 실사 화풍부터 | 샷당 +0.08 USD | **키프레임 규칙(PRD 6.5: 1인 · AI 이미지만) 확대 승인**. 2인 · 애니는 필터 실측 후 |

L3 주의: 일러스트 2인 컷은 Luma 필터 통과 0/4, 실사 변환 2/2, 1인 2/2(PRD 5.1 실측). 실패하면 기존 E5(텍스트 전용 1회 자동 재제출)가 받는다.

## 5. 지키는 규칙

- vpoc 이름공간만 · 플랫폼 파일 수정 금지 · `server.py` 는 등록 한 곳만(`AI-POC-whynot/CLAUDE.md`)
- 기존 PlanView 키 · 액션 응답 불변(추가만) · 스위치 하나로 이전 동작 복귀
- 조용한 절단 · 조용한 모델 대체 금지(R4 · D-L05)
- 완료 증거는 dev 브라우저 재생뿐(R3). 정적 검사 통과는 완료가 아니다
- 비용은 원장에 기록(상한 없음, D-L01). 실험 영상 · 프롬프트는 `run-log` 에 샷별로 남긴다
