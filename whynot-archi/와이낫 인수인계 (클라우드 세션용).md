## 3. 배포 구조 (와이낫)

```
브랜치 push → MR → CI green → main 병합
  main 파이프라인:
    check:whynot            python -X utf8 AI-POC-whynot/tools/check_vpoc.py  (로컬도 같은 명령)
    probe:whynot:images     ECR 불변 태그 확인
    build:whynot:app        → 허브 ECR whynot-app:ci-<sha8>
    build:whynot:frontend   → 허브 ECR whynot-frontend:ci-<sha8>
    deploy:whynot:dev       (자동) ai-deploy 저장소 whynot/dev 에 매니페스트 커밋 → ArgoCD whynot-dev 가 동기화
    deploy:whynot:prod      (수동 ▶, 설계자 승인 후) 같은 ci-<sha8> 이미지를 whynot/prod 로 승격 → ArgoCD whynot-prod
```

| 항목 | 개발계 | 운영계 |
|---|---|---|
| 주소 | `dev-whynot.meta-clouds.com` | `whynot.meta-clouds.com` |
| 계정 | 730335451955 (통합계정 · 프로필 `ai-poc-hub`) | 089540175779 |
| 클러스터 | `AI-POC-eks`(엔드포인트 비공개 → kubectl 은 배스천) · ns `whynot` | `whynot-prod-eks` |
| 선언 | `tenants/whynot/dev.yaml` (active) | `tenants/whynot/prod.yaml` (**blocked — H-01 자격증명 없음, REPLACE-ME 값 미실측**) |
| 렌더 원본 | `deploy/config.env.example` (+ `config.prod.env` 오버레이). 템플릿에 새 `${VAR}` 를 쓰면 반드시 example 에 키 추가 | 같음 |

규칙(`AI-POC-whynot/CLAUDE.md` · steps.md 공통 규칙):
- 개발 배포 경로는 **main 푸시뿐.** `deploy/deploy.ps1` 이나 배스천 `kubectl apply/edit/set/scale/delete` 금지(ArgoCD selfHeal 이 되돌림). 조회(`get`·`logs`·`describe`)는 가능
- `glab ci run`(수동 파이프라인) 금지 — 과거에 레거시 배포가 켜진 사고
- Terraform 실행 · S3/Neptune 데이터 삭제 · `docs/vendor` 삭제 · 운영 배포(승인 전) 금지
- 배포 확인은 파이프라인 success 가 아니라 실측: `/api/health` 의 `build.imageTag == ci-<sha8>` (롤아웃 1~2분 지연)
- 완료 증거는 정적 검사가 아니라 **dev 브라우저에서 영상이 재생되는 것**

## 4. 저장소 공통 규칙 (모든 고객 공통)

- 한 worktree 에 세션 하나. 다른 고객 디렉터리 · 그 CI job · Kiro 파일(`.kiro`) 수정 금지
- 공용 플랫폼 파일(`PLATFORM_FILES.txt`: `gateway.py` · `graph_store.py` · `frontend/Dockerfile` 등)은 고객 디렉터리에서 고치지 않는다
- MR 병합: `glab mr merge <n> --sha <sha> --yes` — 그 sha 의 파이프라인이 모두 끝난 뒤. `platform-drift` 잡은 실패 허용(이전부터)
- 커밋 메시지 끝: `Co-Authored-By: ...` · MR 설명 끝: `🤖 Generated with [Claude Code](...)`
- 자격증명 · 키 값은 출력 · 기록 · 커밋 금지. 계정 명령 전 `aws sts get-caller-identity --profile <p>` 로 계정 확인
