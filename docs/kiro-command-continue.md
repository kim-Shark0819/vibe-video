[작업 규칙 — 끝까지 지킨다]

W-3 "없다·안 쓴다" 판정 전에 git fetch 후 origin/main 과 관련 브랜치를 모두 확인한다(git ls-tree origin/main 등).

W-4 배스천: 임시 파일은 /tmp/kiro-<날짜>-<작업명>/ 아래에만 두고 끝나면 그 디렉터리만 지운다.
    kubeconfig 도 그 디렉터리에 따로 둔다(KUBECONFIG 지정). 다른 작업이 돌고 있으면 그 출력을 내 결과로 쓰지 않는다.
    로컬 aws CLI 로 되는 조회는 배스천을 쓰지 않는다. 고객사 계정 dev EKS 는 배스천이 아니라 로컬에서 조회한다.
W-5 비밀값: 값을 대화로 받거나 출력하지 않는다. 필요한 비밀은 그 고객 계정 Secrets Manager 에 이름만 만들고
    (예: whynot-dev/ark-api-key, 값 없음), 설계자가 콘솔에서 값을 넣는다. 보고에는 비밀 이름만 적는다.
W-6 추측은 "가설"이라고 표시하고, 확인 전에는 결론으로 쓰지 않는다.
W-7 운영 규칙은 그대로다: 운영은 하나도 바꾸지 않는다. 운영인지 모르면 운영으로 본다.

    steering 파일(inclusion: always) 변경. 체커 기준은 완화하지 않는다.
