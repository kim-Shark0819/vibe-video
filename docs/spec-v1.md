# vibe-video v1 기능 명세 (2026-09-30)

설계자 결정(2026-09-30)으로 새로 만든다. 기존 `AI-POC-whynot` vpoc1 코드는 받지 않는다 — 문서(`whynot-archi/`)의 **실측 사실과 교훈만** 가져오고 코드는 이 저장소에서 처음부터 쓴다.
테스트는 설계자가 한다. 이 저장소는 코드 보관 · 전달용이고, 실제 실행 · 배포 위치는 설계자가 정한다(0장).

---

## 0. 설계자 결정 (2026-09-30)

| # | 결정 |
|---|---|
| 1 | 코드는 이 세션에서 새로 만든다 (기존 코드 zip 없음) |
| 2 | 주어진 자료는 `whynot-archi/` 가 전부다 |
| 3 | **품질 = 사용자 명령이 영상에 얼마나 반영됐는가.** 사용자가 쓴 뒤 남기는 점수 + 좋은 점 / 아쉬운 점 리뷰로 기준을 잡는다 |
| 4 | 테스트는 **540p**. 월 1회 최종 확인만 **720p** (1회 = 영상 1편) |
| 5 | **영상 길이 15초** |
| 6 | 캐릭터 이미지를 먼저 만들고 **사용자가 확정하면** 영상을 만든다 |
| 7 | 구현이 끝나면 설계자가 테스트한다 |

## 1. 흐름 — 5단계

```
① 명령 입력 → ② AI 해석 확인 → ③ 캐릭터 이미지 확정 → ④ 15초 영상 → ⑤ 리뷰
```

| 단계 | 화면 | 사용자 | 서버 | 유료 호출 |
|---|---|---|---|---|
| ① 명령 | 명령 입력칸 1개 + (선택) 캐릭터 이름 · 설명 | 입력 → [AI 해석] | 저장 → 해석 작업 | Claude 1회 |
| ② 해석 | **명령 반영 체크리스트**(명령을 요소로 쪼갠 목록) · 이야기 · 캐릭터 시트 · 화풍 · 15초 연출안(샷 3개와 각 샷이 반영하는 요소) | 고치기 → [캐릭터 그리기] | 캐릭터 이미지 생성 | SD3.5 × 캐릭터 수 |
| ③ 캐릭터 | 캐릭터별 이미지 · [다시 그리기(의견 입력 가능)] · [확정] | 전원 확정 → [영상 만들기] | 확정 이미지에서 **영상용 외형 문장 확정**(Claude 비전 1회) → 샷 프롬프트 조립 · 검사 | Claude 1회 |
| ④ 영상 | 샷 3개 진행 상태 · 15초 합본 플레이어 | 비용 확인 → [시작] | Luma 제출 · 조회 · 합본 | Luma × 3 |
| ⑤ 리뷰 | 영상 + 체크리스트 | **전체 점수 1~5** · 요소별 반영 여부(반영됨 / 일부 / 안 됨) · 좋은 점 · 아쉬운 점 → [리뷰 저장] | 리뷰 저장 | 없음 |

되돌리기: 지난 단계로 가서 고치면 뒤 단계는 '다시 만들어야 함'이 된다(생성 중인 영상은 취소되지 않고 비용이 나간다 — Bedrock 비동기 API 에 취소가 없다).

## 2. 15초 만들기

| 항목 | 값 | 근거 |
|---|---|---|
| 구성 | **5초 × 3샷 → 합본 15초** | Luma Ray2 길이는 `5s` · `9s` 뿐이다. 9+5=14초라 15초가 안 된다 |
| 해상도 | 540p (월 1회 720p) · 16:9 · 무음 | 결정 4 |
| 비용 | 540p 3 × 3.75 = **11.25 USD/편** · 720p 3 × 7.50 = 22.50 USD/편 | PRD 5.1 단가 |
| 소요 | 동시 제출 한도 1 → 순차. 샷당 실측 72초 ~ 보통 2~5분 → **약 4~15분/편** | Gate 0 실측 |
| 합본 | 3개 MP4 를 ffmpeg 로 이어 붙인다(스트림 복사 → 실패 시 재인코딩 1회) | vpoc1 E15 |
| 샷 연결 | 3샷이 한 장면의 **시작 → 전개 → 끝** 이 되게 연출한다. 장소 1곳 · 조명 · 색감 공통(작품 룩) | D-L13 |

## 3. 명령 반영 — 품질의 중심 (결정 3)

### 3-1. 명령 요소 체크리스트

② 해석에서 AI 가 사용자 명령을 **검사 가능한 요소**로 쪼갠다.

| 예) 명령: "비 오는 밤 골목에서 우산을 든 여자가 누군가를 기다리다 미소 짓는다" |
|---|
| E1 인물: 여자 1명 · E2 소품: 우산 · E3 장소: 골목 · E4 시간 · 날씨: 밤, 비 · E5 동작: 기다린다 · E6 변화: 미소 짓는다 |

- 모든 요소는 최소 한 샷에 배정되어야 한다. 배정 안 된 요소가 있으면 코드 검사에서 막고 AI 에 1회 재요청.
- 사용자는 ②에서 요소를 고치거나 더할 수 있다.
- ⑤ 리뷰에서 요소별로 "반영됨 / 일부 / 안 됨" 을 누른다 → **명령 반영률 = 반영됨 비율** 이 첫 품질 지표가 된다.

### 3-2. 연출 단계 (명령 → 세부 프롬프트)

`whynot-archi/plans/prompt-quality-plan.md` 2장을 그대로 쓴다.

- 작품 룩 1개(색감 · 조명 · 렌즈 질감 · 분위기) — 모든 샷 공통
- 샷별: 5초 안의 변화(시작 → 끝) · 구도 · 빛 · 디테일 · 카메라
- 인물: ③에서 **확정 이미지를 보고** 만든 영상용 외형 문장(약 100자) — 모든 샷에 글자 하나 다르지 않게
- 조립 규칙: 영어만 · 이름 대신 지칭 · 부정어 금지 · 1,200자 이하 · 넘으면 자르지 않고 '검토 필요'

### 3-3. 리뷰를 쓰는 방법

| 단계 | 리뷰 사용 |
|---|---|
| v1 | 저장하고 목록 · 평균 · 반영률만 보인다. 영상 · 프롬프트 · 명령 · 리뷰를 한 묶음으로 남긴다 |
| v2 (리뷰가 쌓인 뒤) | 점수 낮은 리뷰의 "아쉬운 점" 을 모아 연출 지시문에 **주의사항**으로 넣는다. 점수 기준표를 설계자와 확정 |

## 4. 모델 (문서 실측 기준, 바꾸지 않음)

| 용도 | 모델 ID | 리전 |
|---|---|---|
| 해석 · 연출 · 외형 문장 | `global.anthropic.claude-sonnet-4-5-20250929-v1:0` | ap-northeast-2 |
| 캐릭터 이미지 | `stability.sd3-5-large-v1:0` | us-west-2 |
| 영상 | `luma.ray-v2:0` | us-west-2 |

지켜야 할 실측 사실(vpoc1 에서 가져옴):

- Luma `clientRequestToken` 은 `[a-zA-Z0-9](-*[a-zA-Z0-9])*` — 밑줄 금지
- 빈 프롬프트는 API 검증을 통과해 과금 작업이 된다 → 제출 전 로컬에서 막는다
- 출력은 us-west-2 버킷 필수. 파일명을 가정하지 말고 출력 접두사를 나열해 `.mp4` 를 찾는다
- 출력 Content-Type 이 `application/octet-stream` → presign 때 `video/mp4` 로 덮는다
- presigned URL 은 메서드에 묶인다 → 확인은 GET + `Range: bytes=0-0`
- 동시 요청 쿼터 1 → 샷 순차 제출. Throttling 은 대기 후 재제출
- SD3.5 `finish_reasons` 가 null 이 아니면 필터 — 시드만 바꿔 1회 재시도
- Claude 출력은 도구 1개 강제 + 코드 검사 + 위반 시 1회 재요청. 읽기 시간 300초
- 조용히 자르거나 다른 모델로 바꾸지 않는다. 실패는 AWS 원문을 화면에 보인다
